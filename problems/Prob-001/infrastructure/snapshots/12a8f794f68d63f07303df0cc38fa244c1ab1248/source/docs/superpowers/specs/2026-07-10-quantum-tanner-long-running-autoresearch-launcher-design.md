# Quantum Tanner Long-Running Autoresearch Launcher Design

Date: 2026-07-10

## Goal

Add one operator-facing command that repeatedly asks Codex CLI to propose
non-toric quantum Tanner constructions and then evaluates accepted proposals
through the existing deterministic AutoQEC pipeline:

1. validate the AI response and reject invalid or repeated proposals;
2. materialize finite CSS instances with `qec-code`;
3. find and verify X-like code-distance upper-bound witnesses;
4. complete logical-X observables;
5. run the fixed `p=0.001` rbposd OSD10 benchmark;
6. compare each result with copied single-logical rotated-surface baselines;
7. feed compact structured evidence into the next proposal round.

The launcher must support long runs without accumulating an unbounded Codex
conversation context. Its durable state must live under an operator-selected
work root, outside the source checkout.

## Operator Interface

The new entry point is:

```bash
QEC_CODE_BIN=/path/to/qec-code \
RSINTER_BIN=/path/to/rsinter \
scripts/run_quantum_tanner_autoresearch.sh \
  --work-root /tmp/autoqec-qt-long \
  --rounds 20 \
  --proposals-per-round 4 \
  --max-group-order 64 \
  --max-physical-qubits 512 \
  --run-wall-clock 30m
```

Required arguments:

- `--work-root`: a path outside the caller checkout where all durable state is
  stored;
- `--rounds`: a positive, finite target number of completed proposal rounds.

Optional arguments provide conservative defaults for proposal count, group
order, physical-qubit limit, per-round decoder wall clock, and Codex model.
`CODEX_BIN`, `QEC_CODE_BIN`, and `RSINTER_BIN` environment variables override
the three external executable paths.

`--resume` reopens an existing work root. The launcher rejects configuration
drift on scientific parameters, while allowing the target round count to be
increased. It never deletes or overwrites a previous attempt.

## Architecture

The launcher is a shell orchestrator over existing AutoQEC CLI commands. Each
proposal round receives a fresh local clone of the source commit recorded in
the top-level state file. Uncommitted caller changes are not copied into a
round; the launcher prints a warning when the source checkout is dirty and
records the exact source commit used.

Codex is invoked once per round with:

```text
codex exec --ephemeral --sandbox read-only --output-schema <schema> \
  --output-last-message <response> -
```

The prompt requests non-toric `lr_cayley_no_cover_v1` proposals and delegates
the finite group, inverse-closed A/B generator sets, and GF(2) local parity
checks to the model. Codex does not run the numerical pipeline and receives no
write access. The response schema generated by
`prepare-quantum-tanner-ai-batch` constrains its final message.

Every round starts a fresh ephemeral Codex session. The only cross-round model
context is a compact JSON feedback record containing all accepted proposal
fingerprints and cumulative rejection-kind counts. This prevents conversation
history and decoder logs from consuming the next round's context window.

The deterministic portion of a successful round is:

```text
prepare request
  -> codex structured response
  -> ingest and validate
  -> materialize accepted proposals
  -> import a proposal-only search space
  -> find and attach X upper-bound witnesses
  -> complete X observables
  -> validate workspace
  -> run autoresearch at p=0.001
  -> compare copied surface baselines
  -> summarize feedback
  -> update cumulative state
```

The launcher reuses the existing campaign, benchmark suite, proposal schema,
materializer, witness finder, run loop, surface comparison, and AI feedback
reporter. It does not add a second implementation of those contracts.

## Durable State

The work root contains:

```text
<work-root>/
  state.json
  cumulative-feedback.json
  rounds/
    round-0001/
      attempt-001/
        status.json
        checkout/
        request/
        response.json
        ingested/
        logs/
    round-0002/
      attempt-001/
        ...
```

`state.json` records the launcher schema version, source commit, immutable
scientific configuration, target rounds, completed rounds, next round, and
the latest successful attempt for every completed round.

Each attempt writes stage transitions to `status.json`. A completed numerical
round points to the autoresearch run root, surface comparison, and feedback
artifacts inside its checkout. A proposal-only round with zero accepted
proposals is also considered completed after its rejection feedback has been
merged into cumulative state.

State updates use write-then-rename semantics so interruption cannot leave a
partially written top-level state file.

## Resume And Failure Semantics

The launcher stops with a nonzero status on:

- missing or incompatible external executables;
- Codex execution failure;
- malformed model output or response-schema failure;
- materialization, witness, observables, workspace validation, decoder, or
  report failure;
- scientific configuration drift during `--resume`;
- a historical proposal fingerprint that was already accepted in an earlier
  round.

An interrupted or failed attempt remains unchanged. `--resume` creates the
next numbered attempt for the same round from a fresh clone. Completed rounds
are never rerun. SIGINT and SIGTERM mark the active attempt interrupted when
possible before returning nonzero.

If a valid response contains no accepted proposals, the round records the
typed rejection evidence, updates cumulative feedback, and continues. This is
a scientific outcome rather than an infrastructure failure.

The target round count is always finite. Operators can emulate an open-ended
campaign by choosing a large target, stopping with Ctrl-C, inspecting evidence,
and resuming with the same or a larger target.

## Historical Deduplication

The compact cumulative feedback is included in every Codex prompt, but prompt
guidance is not the enforcement boundary. After ingestion, the launcher checks
every accepted fingerprint against `state.json`. A historical duplicate fails
the attempt before `qec-code` or `rsinter` is invoked. Within-batch duplicates
continue to be handled by `ingest-quantum-tanner-ai-batch`.

## Documentation

The repository root README gains a concise Quantum Tanner long-run entry and a
link to the campaign guide. The detailed campaign README gains:

- prerequisite and authentication checks;
- a copy-paste launch command;
- parameter definitions;
- output layout and report locations;
- stop and resume commands;
- context and token behavior;
- a warning that upper bounds are screening evidence, not exact distance;
- a small smoke command distinct from a real long-running campaign.

## Verification

Automated tests use fake `codex`, `qec-code`, and `rsinter` executables. They
must prove:

1. a two-round command creates two independent Codex invocations and finalized
   run evidence;
2. the second prompt receives cumulative feedback from the first round;
3. model output is constrained through `--output-schema` and captured through
   `--output-last-message`;
4. all-invalid proposals complete a proposal-only round without decoder work;
5. a failed attempt is preserved and `--resume` creates a new attempt;
6. historical fingerprints are rejected before numerical backends run;
7. configuration drift is rejected on resume;
8. documented commands and launcher help remain synchronized.

The existing real-backend Quantum Tanner AI smoke remains the numerical
integration gate. The launcher test suite must not invoke a live Codex model or
consume model tokens.

## Non-Goals

- cluster or SLURM scheduling;
- exact code-distance certification;
- automatic Zoo promotion from upper-bound evidence;
- one persistent Codex conversation across all rounds;
- silently retrying deterministic backend failures;
- an unbounded default loop.
